# Verified Darwin installation locations

Experimental candidate against `7e5d26989e3af74214cb34274c3220db423a8ae7`; production adoption requires repeated build validation. Stable Zig 0.17.0, stock Rust 1.97.1, macOS 27 / M3 Ultra, eight Cargo jobs, actual dirty-source Harness snapshot `32b41cb0bff55e3c9cbfab3012acec2b179ad199`, release `harness-adapters`. This is a library package, not the full GUI.

The earlier location experiment rejected every Cargo request because Cargo supplies `DYLD_FALLBACK_LIBRARY_PATH`. Its inactive timings did not prove optimization. This candidate narrowly proves that fallback search cannot select an alternate compiler driver at startup: direct canonical stock compiler, one installed `@loader_path/../lib` rpath, exactly one `@rpath/librustc_driver-*.dylib` dependency, existing canonical installed driver with only absolute system dependencies. Driver and compiler content remain in the existing installation fingerprint and every memo stamp is rechecked. Unsupported load commands, paths, symlinks, other loader variables, explicit targets/sysroots, proxies and other versions retain live queries. No compiler-reported installation path is guessed.

Apple's [dyld loader](https://github.com/apple-oss-distributions/dyld/blob/main/dyld/Loader.cpp) and [run-path documentation](https://developer.apple.com/library/archive/documentation/DeveloperTools/Conceptual/DynamicLibraries/100-Articles/RunpathDependentLibraries.html) inform this narrow proof. An actual process observation with `DYLD_PRINT_LIBRARIES` verifies that an invalid same-name shadow driver in the fallback directory is ignored. The compiler's actual installed driver is loaded. `DYLD_LIBRARY_PATH` continues to decline location reuse. [Regression runner](../benchmarks/experiments/rust_fallback_locations_check.py), [results](../benchmarks/rust-fallback-locations-check.json).

The initial three alternating fresh-cache pairs have median 18.479956 s baseline and 17.782763 s candidate (about 3.8% less time), with three wins. Every candidate build records **169 actual collector reuse calls**; baseline records zero. All 193 Rust/native/producer artifact hashes agree. Unlike the previous inactive experiment, coverage is checked from actual collector traces, not inferred from timing or memo fields. [Raw first batch](../benchmarks/harness-rust-fallback-cold-first.json). Its measured runner's boilerplate says four jobs, but the recorded `jobs: 8` and actual `-j 8` command are authoritative; the next runner corrects the descriptive label.

The [confirmation batch](../benchmarks/harness-rust-fallback-cold-confirm.json) also wins 3/3 pairs, but its medians are much closer: 18.231395 s baseline versus 18.161415 s candidate (about 0.4%). All collector coverage and artifact checks pass. This is six directional wins, with substantial session variation; the initial 3.8% difference is not a dependable universal gain. A [new kache comparison](../benchmarks/harness-rust-fallback-kache.json) tests the actual competitor directly.

## Actual kache comparison

Three new alternating cold pairs retain every mode's own complete artifact hashes. Nano median is **18.044749 s** versus **17.563981 s** for kache; kache wins all three pairs. Three rotating clean-target warm builds give **1.796048 s Nano** versus **1.217650 s kache**, again with all three comparisons favoring kache. Nano has 167 Rust and 24 native hits on each warm build. This candidate has **not beaten kache** and remains isolated; no production runtime change is adopted in this experiment.

The [portable C/C++ trial](../benchmarks/harness-portable-fallback-kache.json) gives 2.826624 s Nano versus 1.584697 s kache across three warm samples, with substantial timing variation. It records **24 native bypasses per build and zero portable native hits**. Its single cold sample is not a repeated cold comparison. This trial establishes missing eligibility coverage, not a portable-cache optimization gain. Ring explicitly requests `-gfull` on Darwin, which the current portable adapter refuses; loader-environment and inline-assembly rules can also refuse jobs. The next implementation needs actual command coverage plus dependency and output regressions. Broadly removing refusal gates would not be supported by this experiment. An [untimed native command capture](../benchmarks/harness-portable-command-coverage.json) verifies the actual 24 jobs: 13 C sources and 11 preprocessed assembly sources. All pass `--target=arm64-apple-macosx` and `-gfull`; both are outside the portable parser's current allowlist. Assembly is also outside its source scope. These specific gaps must be addressed before portable-path timing can measure cache restores.

Both modes occupy one stable Rust wrapper path and share an identical complete environment, output path and fixed accepted native Clang adapter. Each build deletes both cache and Cargo target, retains full content hashing and records 167 Rust plus 24 native misses, with zero hits. OS filesystem caches remain warm; R2, dependency fetching and daemon startup are outside timing. All tracked Rust sources/manifests/lockfile remain unchanged. Three failed feature probes are expected and do not fail Cargo.
