# Opt-in Cargo build-script execution cache

Nano can cache a deterministic Cargo build script's flat OUT_DIR files and stdout/stderr under an explicit per-package input contract. Set `NANOCOMPILE_BUILD_SCRIPTS_FILE` to an absolute JSON file and use Nano as `RUSTC_WRAPPER`. Scripts without a matching contract execute normally.

```json
{"schema":1,"packages":[{"package":"my-package","inputs":[".","/absolute/path/to/schema.json"],"tools":[],"installed_inputs":[]}]}
```

Optional `environment` rules constrain execution eligibility: `{"name":"MODE","value":"bundled"}` requires the exact value, while `{"name":"EXTERNAL_INCLUDE","value":null}` requires absence (an empty value is still present). These checks run when the shim executes; Cargo need not supply runtime feature selectors while compiling it. A mismatch runs the real script. The complete environment still enters the cache key.

`tool_selection` rules such as `{"tool":"ar","path":"/usr/bin/ar"}` require that resolved executable path and fingerprint its installed contents. Declare runtime resources and children separately; this is a selection guard, not automatic read discovery. A mismatch or unavailable tool runs the real script.

Relative inputs resolve from the script's package working directory. Declare every read, including headers, assembly includes, generated inputs, external configuration, tool executables and their resources/runtime dependencies. Missing paths and complete directory membership participate in validation. The complete caller environment, arguments, working directory, real script binary, contract bytes and Rust compiler identity enter the key. Mutable input contents are fully hashed on every invocation; mutable symlinks and special input files cause normal execution.

`tools` records PATH/absolute executable selection and installed executable contents. `installed_inputs` records trusted installed files/trees and resolved links; it fully fingerprints initial contents and then validates all installation/link stamps. These fields do not discover a tool's dynamic loads or children. Declare those too. `apple_native` additionally records the default Apple cc/Clang/linker/SDK resources; `apple_tools` queries xcrun live and accepts only thin executable helpers with ordinary absolute system startup loads. Custom compilers, flags or archive chains still need their actual inputs declared. The [Harness archive-chain example](../benchmarks/experiments/build_script_execution/archive-chain-harness-contract.json) is specific to this local CLT installation; regenerate the helper/library paths when selecting another installation.

The contract promises deterministic behavior from declared contents, tools and environment; writes only to OUT_DIR/stdout/stderr; and no background writers. Clock, random, network, metadata-dependent reads and executable-basename-dependent behavior do not qualify. Eligibility requires /dev/null stdin, an initially empty writable/searchable OUT_DIR and flat regular-file outputs (at most 50,000 files and 1 GiB). Nested or special outputs execute each time. Failed scripts retain their exit status and are never cached. Jobserver descriptors survive execution and fallback.

The fresh full content snapshot and tool selection run with independent allocators and join before lookup. Restoration compares the complete stored dependency graph against that snapshot, verifies every artifact and stream blob, writes into a private sibling directory and rechecks input state and membership before atomic publication. This invocation-local state guard never substitutes persistent source metadata for content hashing. A restore I/O error fails without replay or partial OUT_DIR contents; cache-storage failure preserves successful real execution. OUT_DIR permissions are retained.

`nanocompile stats` reports script hits, misses, bypasses and failures. `nanocompile clear` removes script receipts and installed-tree records with the compiler entries/blobs. R2 snapshots currently transport compiler entries/blobs, not script receipts; scripts execute again after such a remote restore. Per-script phase diagnostics require both `NANOCOMPILE_SCRIPT_PROFILE=1` and `NANOCOMPILE_TRACE=1`; the comparison runner exposes `--script-profile`. Diagnostic builds are separate from performance benchmarks.

The real Cargo fixture runs in Linux/macOS CI and checks preserved-mtime edits/reverts, tools, installed links/membership, environment, stdin, failure exits, jobserver descriptors, exact unprofiled streams, corrupt entries, permission failures, read-only output rejection, output permissions and cache clearing. Unit tests force changed inputs and newly present negative inputs between hashing and publication, and reject an omitted dependency. The [local final-binary fixture](../benchmarks/build-script-cache-production-fixture.json) records the exact executable and test hashes.

## Measurements

[Ten alternating snapshot-reuse pairs](../benchmarks/script-snapshot-reuse-profile.json) measure the same real ring script and primed entry: 82.813ms before versus 78.660ms after (seven candidate wins). [Ten independent validation-overlap pairs](../benchmarks/script-validation-overlap-profile.json) measure 63.979ms serial versus 47.071ms overlapping (ten candidate wins, 26.43% median reduction). Each session fixes script, environment, cache and output paths and validates all own-prime output hashes and normalized streams. Wrapper diagnostic lines are excluded from stderr equality. Compare within a session; these are isolated diagnostic script measurements, not whole-build gains. The [runner](../tests/script_restore_profile.py) retains frozen binary, real executable, Cargo log and contract hashes.

[Three full Harness pairs](../benchmarks/harness-validation-overlap.json) use the frozen overlapping candidate, real dirty adapters snapshot, eight jobs, Rust 1.97.1, kache 1.0.0 and the explicit archive-chain contract. Cold medians are Nano 16.581986s and kache 16.906374s, with two Nano pair wins; warm medians are 0.926325s and 1.158305s, with all three Nano wins. Every repeated rlib, macro dylib, script launcher and native output matches its implementation's own cold hashes. This is the adapters library, not the complete GUI; caches/targets are cleared for cold pairs, OS caches remain unflushed, and R2 is excluded. The cold lead remains variable. Differences between separate full-build sessions do not establish the marginal gain of overlapping validation. The stats/clear, output-permission and loader-environment guards in the final accepted binary were verified separately; these timings refer to the frozen candidate recorded in the report.

## Guarded bundled SQLite candidate

The [local Harness contract](../benchmarks/experiments/build_script_execution/sqlite-harness-contract.json) adds `libsqlite3-sys` 0.30.1's bundled build to the existing archive-chain ring example. It is deliberately scoped to the measured native Apple ARM configuration: copied bundled bindings, default compiler/archive tools and audited header/resources. Alternate binding/SQLCipher/pkg-config modes, custom native flags, include paths and tool overrides are refused. Cargo's ordinary loader fallback environment remains allowed by the existing absolute-system-startup proof; other loader overrides remain refused.

This file is a local example, not a portable auto-detection policy. Regenerate its expected `RUSTC_WRAPPER`, host/target, selected tools and CLT resources for the actual runner; changing these must preserve the audited behavior and complete declared inputs. The pinned wrapper basename is `nanocompile`, which the inspected `cc` crate does not treat as a native compiler proxy. `R2` does not transport execution receipts yet.

The [actual SQLite fixture](../tests/sqlite_execution.py) copies the package privately and checks full native output/stream equality, repeated hits, preserved-mtime C/header edits, linked-library behavior, reverts, guarded native flags, exact failed-script exits, output tampering and blob repair. This verifies the scoped execution path; full Harness benchmark results are separate and remain required before claiming a project speed win.
