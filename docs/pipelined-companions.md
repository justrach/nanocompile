# Compiler pipelining with guarded archive companions

This opt-in variation repairs the warm-cache regression in the [streaming experiment](harness-streaming-experiment.md). Enable both `NANOCOMPILE_STREAM_COMPILER=1` and `NANOCOMPILE_PIPELINED_COMPANIONS=1` for experimental comparisons. Defaults remain unchanged pending broader validation.

Nano's dependency collector already proves that metadata-only Rust library compilation ignores an exact same-stem archive when matching metadata is selected. Its directory membership guard nevertheless treated the archive appearing after metadata as an input change. That rejected cache stores during pipelining. The variation records a distinct membership digest that omits only that proven regular archive entry. Matching metadata must be present as a regular file in both snapshots; its entire bytes remain a dependency. All other prefix candidates, metadata removal or corruption, candidate kind changes, proc macros, explicit archive inputs, native linkage and broad fallback keep their existing guards. Restore requires the guarded metadata entry to remain present, and rechecks every dependency and output blob.

The [actual rustc probe](../benchmarks/pipelined-companion-priority.json) checks ignored corrupt archives, archive absence/reappearance, a companion kind change, complete metadata bytes with preserved timestamps, competing libraries, archive fallback and explicit archive failure. A native test proxy runs real rustc and publishes a valid unused archive before returning to Nano. This deterministically changes membership within Nano's compilation interval; the resulting entry stores and restores successfully. A linked executable still prints the expected value. The probe isolates kind-change variants so bounded cache-history eviction does not confound revert expectations.

[Three untraced Harness cold pairs and three warm rounds](../benchmarks/harness-pipelined-companions.json) use the real adapters snapshot, Rust 1.97.1, kache 1.0.0, eight jobs, the same explicit ring contract and producer options as previous trials. Nano wins all three cold pairs: median 15.795684s versus 16.928929s, 6.7% lower. It also wins every warm round: median 0.929687s versus 1.138941s, 18.4% lower. Every cold run has 167 Rust misses and one build-script miss, and every warm run has 167 Rust hits and one script hit. All repeated rlibs, macro dylibs, script launchers and real executables, native objects and archives match each implementation's own cold outputs. This is the library workload, not the complete Harness GUI build. OS caches are unflushed; fetching, daemon startup and R2 are excluded.
