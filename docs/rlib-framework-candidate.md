# Opt-in command-line framework metadata

The full-Harness LTO profile records a warm `wry` request taking 0.816 s because `-l framework=WebKit` is refused. Source-attribute framework metadata already has real native-metadata checks; this candidate extends the command-line form for a plain native macOS Rust library.

Set `NANOCOMPILE_RLIB_FRAMEWORKS=1`, or pass `--rlib-frameworks` to the full project comparison and full-app source-edit runners. It accepts only plain `framework=Name` arguments with simple names and a single `lib`/`rlib` output type, on the native macOS target. Explicit targets, modifiers, dynamic library kinds and framework-bearing executable/proc-macro producer jobs retain passthrough. Existing source, Rust dependency, native-directory, compiler and output validations remain in place. The control is off by default and is retained in generated future-experiment provenance.

Rust libraries record a framework dependency for final linking rather than bundling that framework. This is the documented [Rust linkage model](https://doc.rust-lang.org/nomicon/ffi.html#linking). Final producer links still require their existing linker input discovery; this option does not authorize an unaudited final link. The real fixture proves that an absent framework can compile into an rlib, while final linking still fails normally.

[Twenty-five real executions](../benchmarks/rlib-framework-fixture.json) use Rust 1.97.1 and native Apple ARM. Direct/cold/hit library bytes and modes match. A preserved-mtime source edit changes a linked Foundation probe from 8 to 9; the revert restores original bytes and returns 8. Changing the framework name gets distinct metadata and cache entries. Missing-framework final links fail; explicit-target compilations, unsupported modifiers and both producer modes preserve direct outputs and streams through fallback. The initial fixture used Objective-C encoding `l` and incorrectly expected size 8; the direct system probe returned 4. The corrected explicit `q` encoding supplies the intended 64-bit check. The original failed state and two subsequent fixture states remain private.

The frozen runtime binary is `15b4b695d9eef11a9dfcf785b3e23c31f464b3cf8a750e1e48e1aadb94e985ea` at `/tmp/nano-framework-trial-20261011/bin/nanocompile`. Its [runtime patch](../benchmarks/experiments/rlib-framework-runtime.patch) applies to `d0d6bb3`. Unit tests, real Rust/Zig integration, existing native metadata fixtures and tracing/provenance tests pass. Linux/macOS CI runs the new fixture; the actual framework cases are macOS-only. No full-Harness speed improvement is claimed yet.

The same patch fixes a separate output-completeness defect. [The earlier frozen runtime audit](../benchmarks/multi-crate-output-baseline.json) confirms that `--crate-type staticlib --crate-type rlib` produces four files cold, but reports a warm hit while omitting `libprovider.a`. Parsing only the last type loses an output. Differing repeated types now bypass until the cache can discover and restore every requested output. Both flag orders are verified against fresh direct bytes and modes. This guard is independent of the framework opt-in.
